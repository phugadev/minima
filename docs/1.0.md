# What 1.0 means

1.0 is a promise to the people who install Minima: the names you build on will
not move under you, and everything shipped has been used for real by someone
other than the system checking itself.

It is not a feature count. Minima could ship ten more components and still not
be 1.0; it could ship none and be 1.0 tomorrow if the gates below held. Every
gate is a runner, not a judgement — if a gate cannot be run, it is not a gate,
it is a hope.

## The gates

All of them, at the commit that gets tagged.

| # | Gate | Proven by | At the 1.0.0 release commit, 27 Sep 2026 |
|---|---|---|---|
| 1 | Every rule has a runner, and every runner passes | `npm run audit` | **Held** — 13 runners, 0 failing |
| 2 | It installs from nothing | a fresh `create-next-app` + `shadcn init` + registry install passes `npm run audit:install`, root check included | **Held** — a fresh install built for the release: 2,410 checks, 0 failing, root 16px in both modes |
| 3 | Two consumers, of two different kinds | `npm run audit:consumers` lists at least two, with different `kind`, on their default branches | **Held** — enrictrillo.com (reading site) and Watchman (dashboard) |
| 4 | Both modes, in production | `audit:consumers` shows light and dark proven, and `npm run audit:pages` passes on each consumer in its modes | **Held** — enrictrillo.com in dark, live: 688 checks. Watchman in light and dark, every route, signed in and out: 6,874 checks. 0 failing |
| 5 | Every shipped item is used | `audit:consumers` coverage: no item without a consumer that imports it | **Held** — all nine items imported. `layout` was installed in Watchman, flagged unused by the audit, and taken out rather than kept for the count; enrictrillo.com uses it |
| 6 | Every consumer is current | `audit:consumers`: every installed file byte-identical to the registry | **Held** — both consumers byte-current, enrictrillo.com after re-adding the theme for the darker light muted |
| 7 | Forks are tracked | `npm run audit:upstream`: no structural upstream change left unported | **Held** |
| 8 | Everything shipped is written down | `audit-registry`: every item named in `docs/install.md` by its address. `audit-changelog`: every commit that changes what ships also touches `CHANGELOG.md` | **Held** |
| 9 | Known limits are decided, not discovered | each limit below has a decision recorded against it | **Held** — the last, subtle ≈ muted in light, decided 27 Sep |

Gate 5 is the one most likely to be met the wrong way. The point is not to find
a use for `tabs` so the box can be ticked; it is that a component nobody needed
is a component nobody tested. If Watchman does not need one of them, it comes
out of the registry before 1.0 rather than shipping on the strength of the lab.

## Known limits

Things that are true, measured, and not going to be fixed by accident.

- **`subtle-foreground` and `muted` in light.** At the generated 0.52, light
  muted sat so near the 4.5:1 floor that the solved subtle level came out the
  same grey, and Watchman — the first consumer to ship light — showed its two
  text tiers reading as one. *Decided (27 Sep):* light muted is darkened to
  0.44 (~7.3:1), still two contrast points under the reading grey, which gives
  subtle 0.057 L of room — close to dark's 0.072 (docs/colour-roles.md §6).
- **Only the four state hues guarantee text on their solid.** Green, amber, red
  and cyan are checked to carry a label on their solid at 4.5:1; orange, teal,
  blue, purple and pink are not, and several could not be without stopping
  being themselves. *Decided:* those five are never a text ground — links,
  rings, tints and data marks only. audit-ramps enforces the guarantee on the
  four.
- **Radius is shadcn's above the two anchored rungs.** `rounded-sm` and
  `rounded-lg` land on Minima's mark and control rungs; the other five are
  shadcn's ratios (docs/install.md). *Decided:* anchor, don't contest;
  `audit:install` prints the ladder so a change upstream is loud.

## What 1.0 promises

The **public API** is the set of names a consumer writes:

- token and role names — `--gray-text`, `--foreground`, `--subtle-foreground`,
  `bg-green-fill`, the step roles (`bg`, `fill`, `border`, `solid`, `text` …)
- utility names — `type-*`, the space rungs (`inset`, `gutter`, `stack`,
  `section`), radius rungs, `shadow-raised` and the other depth names, motion
  durations, `.signal`, `.figure`, `.prose`
- `data-density` and its three values
- registry item names, and each component's exports and props
- what `cn` knows: a utility Minima ships is registered with it

After 1.0:

- **major** — a public name is renamed, removed, or changes meaning (a role that
  starts pointing at a different job)
- **minor** — something is added, or a value is retuned and every audit still
  passes. Values are not the API; roles are. A ramp can be regenerated in a
  minor release, because nothing should be asking for its numbers
- **patch** — a fix that changes no name and no value a consumer can see

Before 1.0 there were no versions at all: work landed on `main` under
`## [Unreleased]`, and the first number anyone saw was the one these gates
earned. That was 1.0.0, on 27 September 2026.

## How 1.0 is cut

1. Every gate above holds at one commit on `main`.
2. The `## [Unreleased]` section becomes `## [1.0.0]`, dated.
3. That commit is tagged `v1.0.0`.
4. Every consumer re-adds from the registry and `audit:consumers` passes — the
   tag is only real once the people it promises something to are on it.

## How a release reaches consumers

There is no package to pin. `npx shadcn@latest add phugadev/minima/<item>`
reads this repository's default branch, so whatever is on `main` is what
every consumer installs the next time they add or re-add an item. A version
number only means something if `main` is always one.

So every merge to `main` is a release:

1. Work happens on a branch, with its changelog entries under `[Unreleased]`.
2. The pull request that lands it moves those entries under a new version
   heading — patch, minor or major, by the rules above — and sets that
   version in `package.json`. `node scripts/audit-changelog.mjs --release`
   checks both before merging.
3. The merge commit is tagged `v<version>`, and the GitHub release carries
   the changelog section.

`audit-changelog` enforces the second step on `main` itself: an `[Unreleased]`
entry there, or a `package.json` version that is not the newest release, fails
`npm run audit`.

## Not in 1.0

- More components. The ones there are have to be earned first.
- Light mode on enrictrillo.com. It proves dark; Watchman proves light.
- A second theme, a Figma library, or anything Minima would have to maintain
  without a consumer asking for it.
